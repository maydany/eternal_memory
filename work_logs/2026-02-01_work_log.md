## 🔧 1. 임베딩 모델 마이그레이션

### 1.1 배경: 스크립트 유사도 격차

**문제 발견**:
- 한국어 쿼리: "내 이름은 성훈"
- LLM 추출: "User's name is Sunghoon" (영어 중심 프롬프트)
- 결과: 한국어 쿼리와 영어 팩트 간 유사도가 0.85 미만
- 영향: Supersede 및 Reinforcement 로직 실패 → 중복 팩트 생성

### 1.2 해결책: text-embedding-3-large 도입

**MIRACL 벤치마크 비교**:
| 모델 | 다국어 검색 성능 |
|------|-----------------|
| text-embedding-ada-002 | 31.4% |
| text-embedding-3-small | 44.0% |
| text-embedding-3-large | **54.9%** (+23.5%p) |

### 1.3 구현 세부사항

#### 스키마 변경
```sql

ALTER TABLE categories ALTER COLUMN embedding TYPE vector(1536);
```

#### 설정 변경
- **이전**: `text-embedding-ada-002` (1536d)
- **이후**: `text-embedding-3-large` (1536d via Matryoshka)

### 1.4 마이그레이션 스크립트

`scripts/migrate_embeddings.py`:
- 동적 차원 설정: `dimensions=1536` 파라미터 지원
- Matryoshka 통합: 1536d에서 고정밀도 유지
- 인덱스 관리: 마이그레이션 후 HNSW 인덱스 재생성


## 🔧 5. 버퍼 플러시 트리거 확장

### 5.1 배경
기존 `beforeunload` 이벤트만으로는 다양한 사용자 상호작용 시나리오를 커버하지 못함

### 5.2 새로운 트리거 추가

| 레이어 | 트리거 조건 | 역할 | 메커니즘 | 소스 |
|--------|------------|------|----------|------|
| 1. Volume | 토큰 임계값 도달 | 효율성 | 자동 플러시 | `threshold` |
| 2. Inactivity | 유휴 타임아웃 | 안전망 | 백그라운드 루프 | `idle_timeout` |
| 3. Session End | 탭/창 닫기 | 데이터 보존 | `beforeunload` + `sendBeacon` | `page_close` |
| **4. Invisibility** | 탭 전환/최소화 | Soft Departure | `visibilitychange` + `sendBeacon` | `tab_hidden` |
| **5. Mobile Hide** | 앱 백그라운드 | 모바일 지원 | `pagehide` + `sendBeacon` | `page_hide` |
| **6. SPA Routing** | 세션 전환 | 컨텍스트 일관성 | `useEffect` + `sendBeacon` | `session_switch` |

### 5.3 구현 세부사항

```typescript
// visibilitychange 이벤트
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') {
    // sendBeacon 사용: 페이지 언로드 중에도 전송 보장
    navigator.sendBeacon('/api/buffer/flush?source=tab_hidden');
  }
});

// pagehide (모바일 Safari 지원)
window.addEventListener('pagehide', (e) => {
  const source = e.persisted ? 'page_hide_cached' : 'page_hide';
  navigator.sendBeacon(`/api/buffer/flush?source=${source}`);
});
```

### 5.4 CORS 및 프록시 고려사항
- **상대 경로 사용**: `/api/buffer/flush` (절대 URL 아님)
- `sendBeacon`은 CORS 정책으로 인해 직접 백엔드 호출 실패 가능
- Vite 개발 프록시를 통해 올바른 헤더 및 포트 포워딩 처리

## 🔧 6. 서버 측 세션 구현

### 6.1 배경: localStorage 제한

**기존 문제점**:
- 멀티 디바이스 분산: 노트북에서 시작한 대화를 모바일에서 이어갈 수 없음
- 버퍼 신뢰성: Tier 2 요약이 브라우저 캐시 초기화 시 손실
- 확장성: 대용량 대화 기록이 localStorage 제한 초과

### 6.2 데이터베이스 스키마

```sql
CREATE TABLE IF NOT EXISTS chat_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL DEFAULT 'New Chat',
    messages JSONB NOT NULL DEFAULT '[]'::jsonb,
    mode VARCHAR(10) NOT NULL DEFAULT 'fast',
    context_summary TEXT,
    summarized_count INTEGER DEFAULT 0,
    selected_message_id VARCHAR(255),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    last_active_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 6.3 Session API 아키텍처

| 엔드포인트 | 설명 |
|-----------|------|
| `GET /api/sessions` | 모든 세션 목록 (경량 메타데이터) |
| `GET /api/sessions/{id}` | 특정 세션 전체 조회 |
| `POST /api/sessions` | 새 세션 생성 |
| `PUT /api/sessions/{id}` | 세션 업데이트 |
| `DELETE /api/sessions/{id}` | 세션 삭제 |
| `POST /api/sessions/{id}/messages` | 메시지 증분 추가 |

### 6.4 증분 동기화 패턴

전체 메시지 배열 재업로드 대신 효율적인 증분 추가:
```sql
UPDATE chat_sessions SET messages = messages || $2::jsonb WHERE id = $1
```

### 6.5 Zustand 스토어 변환

**Hydration 흐름**:
1. 앱 마운트 시 `store.initializeSessions()` 호출
2. `GET /api/sessions`로 경량 메타데이터 로드
3. 각 세션에 대해 `GET /api/sessions/{id}`로 전체 기록 하이드레이션
4. 가장 최근 `last_active_at` 세션 자동 활성화

### 6.6 발견된 문제 및 해결

#### Router Prefix 충돌
- **문제**: `APIRouter(prefix="/sessions")` + `include_router(..., prefix="/api/sessions")` → `/api/sessions/sessions` 경로 생성
- **해결**: `main.py`에서 중앙 관리, 개별 라우터는 prefix 없이 정의

#### JSONB 파싱 이슈
- **문제**: `asyncpg`가 JSONB를 문자열로 반환하여 Pydantic 유효성 검사 실패
- **해결**: `parse_messages()` 헬퍼로 타입 감지 후 필요시 `json.loads()` 적용

#### 중복 상태 해결
- **문제**: `ChatPage.tsx`에서 `contextSummary`, `summarizedCount`를 위한 로컬 `useState` 훅이 Zustand 스토어와 충돌
- **해결**: 로컬 훅 제거, Zustand 스토어의 세션 객체가 단일 진실 소스
